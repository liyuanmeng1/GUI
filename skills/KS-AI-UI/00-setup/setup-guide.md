# KS-AI-UI 开箱引导流程

**本文件用途**：首次使用 KS-AI-UI 时的完整引导流程,仅在 Setup 阶段加载,配置完成后不再使用。

---

## Setup 检测机制

**触发条件**：当检测到以下任一文件为空时,自动进入对应的 Setup 引导

- `01-foundation/dependencies.md` 为空 → 进入 Setup A
- `02-templates/` 下所有模板文件为空 → 进入 Setup B（仅路径 B 需要）
- `03-design-db/` 下所有规范文件为空 → 进入 Setup C

三个 Setup 必须按序完成。完成后自动进入正常生成流程（Step 1-5）。

---

```
生成的代码基于你们自己的组件库，可以直接放进项目使用。

生成的页面将 100% 基于你的团队组件库，符合产品设计规范，可直接交付使用。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

输入 A 接入团队组件库，或输入 1-3 快速体验预置主题
```

---

### 路径 A：团队组件库（推荐）

**用户提供组件库信息后的流程**：

1. **收集用户提供的信息**：
   - 组件库站点链接（文档地址）
   - npm 安装方式

2. **生成并写入文件**：
   - `01-foundation/dependencies.md` — 基于用户提供信息生成的依赖配置
     - **文件头部必须包含**：`<!-- Setup Path: A -->`（标记为团队组件库路径）
   - `01-foundation/theme.ts`（可选）— 如果用户提供了主题配置

3. **同步更新 SKILL.md 开发规范第 1 条**

4. **输出确认信息格式**：
   - 展示配置摘要（框架/组件库/前缀/安装方式/引入方式/文档）
   - 列出已生成的文件
   - 引导进入 Setup B

5. **进入 Setup B**

> ✅ **Setup A（路径 A）完成标志**：`01-foundation/dependencies.md` 已写入且头部包含 `<!-- Setup Path: A -->`,`SKILL.md` 开发规范已更新。

---

### 路径 B：预置主题（快速体验）

**用户选择主题后的完整流程**：

1. **生成主题 Design Token**
   - 基于用户选择的主题（专业蓝/暗夜模式/科技感）
   - 或基于用户自定义描述,生成一套 Ant Design Design Token 配置

2. **自动写入以下文件**：
   - `01-foundation/theme.ts` — 主题 Design Token（完整的 antd v5 token 配置）
   - `01-foundation/dependencies.md` — React + Ant Design + Pro Components 依赖配置
     - **文件头部必须包含**：`<!-- Setup Path: B -->`（标记为预置主题路径）
   - `02-templates/ProLayout.tsx` — 基于 `@ant-design/pro-layout` 的全局布局
   - `02-templates/ProTablePage.tsx` — 基于 `ProTable` 的列表页模板
   - `02-templates/ProFormPage.tsx` — 基于 `ProForm` 的表单页模板
   - `02-templates/ProDescriptionsPage.tsx` — 基于 `ProDescriptions` 的详情页模板
   - `02-templates/StatisticCard.tsx` — 基于 Pro 统计卡片的看板模板

3. **同步更新 SKILL.md 开发规范第 1 条**
   - 将占位内容替换为实际的 React + Ant Design + Pro Components 规范

4. **输出确认信息格式**：
   - 展示选择的主题名称和视觉风格关键特征（主色/背景/圆角/整体感）
   - 列出已生成的文件清单
   - 提示 Setup B 已自动跳过,引导进入 Setup C

5. **Setup B 自动跳过**,直接进入 Setup C

> ✅ **Setup A（路径 B）完成标志**：`01-foundation/` 和 `02-templates/` 下所有文件已写入,`dependencies.md` 头部包含 `<!-- Setup Path: B -->`,`SKILL.md` 开发规范已更新。

## Setup B：页面模板录入

**触发条件**：仅在路径 A（团队组件库）时执行，路径 B（预置主题）自动跳过。

### 引导语

```
📋 接下来需要录入页面模板

页面模板是生成代码的基础骨架,需要提供以下 4 个模板（必填）：

  ① AppLayout     — 全局布局（含顶导、侧导）
  ② ListPage      — 列表页（含搜索、表格、分页）
  ③ FormPage      — 表单页（新建 / 编辑）
  ④ DetailPage    — 详情页（含面包屑、字段展示）
  ⑤ DashboardPage — 数据看板（可选）

你可以选择：

  A. 提供设计稿
     粘贴页面模板的 Figma 链接,并描述页面功能区域定义
     （如搜索区、表格区、操作栏等）
  
  B. AI 自动生成
     基于你的组件库自动生成标准模板
     生成后会在 IDE 中打开预览,你可以确认或调整

回复 A 提供设计稿,或回复 B 自动生成
```

---

### 选项 A：提供设计稿（Figma 链接）

**逐个引导用户提供每个模板的 Figma 链接和功能区域说明**：

```
请逐个提供页面模板的 Figma 链接和功能区域说明

先从 ① AppLayout 开始：

  1. Figma 链接：
     粘贴页面设计稿的 Figma 链接
  
  2. 功能区域说明：
     描述页面的主要区域划分,例如：
     · 顶部导航：logo + 搜索框 + 用户信息
     · 侧边导航：一级菜单 + 二级菜单
     · 主内容区：页面内容渲染区

请提供 AppLayout 的 Figma 链接和功能说明
```

**AI 处理流程**：
1. 读取 Figma 链接（如果可访问,提取设计稿信息）
2. 结合用户描述的功能区域说明
3. 基于 `01-foundation/dependencies.md` 中的组件库生成代码
4. 写入对应模板文件
5. 输出确认信息,继续下一个模板

重复此流程直到 5 个模板全部完成。

---

### 选项 B：AI 自动生成

**AI 自动生成标准模板**：

1. **生成所有模板文件**
   - 基于 `01-foundation/dependencies.md` 中的组件库信息
   - 生成 5 套标准企业级后台模板代码

2. **在 IDE 中打开预览**
   - 自动打开 5 个生成的模板文件供用户查看

3. **用户确认流程格式**：
   - 列出已生成的 5 个模板文件路径
   - 提示已在 IDE 中打开预览
   - 提供确认/替换/继续三种反馈选项

4. **根据用户反馈调整**（如果需要）

> ✅ **Setup B 完成标志**：`02-templates/` 下至少 4 个核心模板（AppLayout、ListPage、FormPage、DetailPage）已写入。

## Setup C：设计规范配置

### 引导语

```
③ 设计规范配置

设计规范用于指导 AI 生成的代码保持视觉一致性,包含：

  📐 设计原则      — 核心设计理念（如克制、扁平化等）
  🎨 排版规范      — 字号层级、颜色系统、间距系统
  ✨ UI 模式       — 品牌风格、颜色语义、空白原则
  ✍️ 文案规范      — 按钮、状态、提示等文案标准

你可以选择：

  A. 使用默认规范
     AI 基于你选择的主题自动生成一套标准规范（可随时修改）
  
  B. 提供已有规范
     粘贴你的设计文档或设计系统链接,AI 会提取关键信息并结构化
  
  C. 口述描述
     告诉 AI 你的设计要求,AI 帮你整理成规范文档
  
  D. 暂时跳过
     先不填写规范,直接开始生成代码（后续可随时补充）

回复 A / B / C / D 选择方式
```

---

### 选项 A：使用默认规范（推荐,大多数用户选择）

**AI 基于 Setup A 选择的主题自动生成 B 端 Web 标准设计规范**

**生成 4 个文件的内容要求**：

#### 1. design-principles.md（设计原则）

包含 5 条核心原则：

- **克制优先** — 界面元素只在必要时出现,默认隐藏非核心操作,避免堆砌信息
- **层级清晰** — 视觉层级通过字号/字重/颜色深浅传达,定义 4 级层级表格（页面标题/卡片标题/正文/辅助）
- **反馈及时** — 用户操作后 300ms 内反馈,loading 状态/Toast 提示/危险操作二次确认
- **框架统一** — 所有页面使用同一套全局框架,保持导航/布局/卡片风格一致
- **扁平化** — 减少视觉噪音,用空白和间距划分区域,而非边框和分割线

#### 2. typography.md（排版规范）

包含：

- **字体** — 系统字体栈定义
- **字号层级表** — 6 级层级（页面标题/卡片标题/正文/辅助文字/标签/小字）,每级明确字号/行高/字重/颜色/适用场景
- **颜色系统表** — 10 种用途色值（主文本/次要/禁用/分割线/背景/主色/成功/警告/危险/白色）
- **间距系统表** — 5 级间距（超小/小/中/大/超大）及适用场景
- **文字截断规则** — ellipsis + Tooltip
- **数字格式规则** — 千分位/百分比/时间/空值显示

#### 3. ui-patterns.md（UI 模式）

包含：

- **品牌定位** — 根据主题调整（如极简克制/专业高效）
- **风格选型表** — 圆角/阴影/边框规范
- **空白原则** — 卡片间距/内容区边缘/表格留白
- **颜色语义表** — 黑/绿/橙/红/蓝的语义定义
- **交互模式** — 表格操作/表单校验/危险操作/加载状态的标准模式

#### 4. copywriting.md（文案规范）

包含 6 类标准文案表格：

- **按钮文案** — 创建/修改/删除/保存/取消/批量操作/刷新
- **状态文案** — 运行中/已完成/失败/等待/已停止/已归档
- **Toast 提示** — 操作成功/失败/网络错误/权限不足/参数错误
- **空状态文案** — 无数据/搜索无结果/引导创建/功能未开通
- **表单提示** — 必填项/格式错误/长度限制/范围限制
- **确认弹窗** — 删除确认/放弃修改/批量操作

**生成后的输出格式**：
- 展示基于主题生成的规范文件清单及要点摘要
- 提示已在 IDE 中打开 4 个文件预览
- 输出配置完成信息,引导开始生成 UI 页面

---

### 选项 B：提供已有规范

**引导用户提供设计文档**：

```
请提供你的设计规范资料

你可以提供以下任意形式：

  · Figma 设计系统链接
  · 公司设计规范文档链接
  · 飞书文档/语雀文档链接
  · 直接粘贴设计规范内容

AI 会自动提取以下关键信息：

  · 字号层级定义
  · 颜色系统（主色、辅助色、语义色）
  · 间距规则
  · 圆角规范
  · 设计原则
  · 文案规范

请粘贴链接或文档内容
```

**AI 处理流程**：
1. 读取用户提供的设计文档（链接或文本）
2. 提取关键信息（字号、颜色、间距、原则、文案等）
3. 结构化整理成 4 个标准规范文件
4. 写入 `03-design-db/` 对应文件
5. 在 IDE 中打开预览
6. 输出确认信息

---

### 选项 C：口述描述

**引导用户描述设计要求**：

```
请描述你的设计要求

你可以从以下方面描述（不必全部回答）：

  1. 设计原则：
     你希望界面遵循什么设计理念？
     （如简洁克制、信息密度高、扁平化等）
  
  2. 字号和颜色：
     有没有特定的字号要求？主色调是什么？
  
  3. 间距和圆角：
     喜欢紧凑还是宽松的布局？方正还是圆润？
  
  4. 文案风格：
     按钮和提示语用什么措辞？正式还是活泼？

随意描述,AI 会帮你整理成结构化规范
```

**AI 处理流程**：
1. 收集用户描述的各项设计要求
2. 补充缺失的标准规范（如果用户没有提及）
3. 整理成 4 个标准规范文件
4. 写入 `03-design-db/`
5. 在 IDE 中打开预览
6. 输出确认信息

---

### 选项 D：暂时跳过

**输出信息格式**：
- 提示已跳过设计规范配置
- 说明 AI 将基于组件库默认样式生成代码
- 告知可随时回来补充规范
- 输出配置完成信息,引导开始生成 UI 页面

> ✅ **Setup C 完成标志**：用户已明确完成规范配置、提供了已有规范、口述了设计要求,或选择跳过。
